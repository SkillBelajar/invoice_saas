# Memori Proyek — SaaS Invoicing & Piutang

**Versi Aplikasi:** 1.4
**Status:** CRM Slice 3 - Fitur Pusat Pesan & Promosi dinonaktifkan sementara (hidden dari menu navigasi & dinonaktifkan rutenya); CSAT Survei, Pipa CRM Deals & Tiket Keluhan tetap aktif.

---

## 1. Ringkasan 5W+1H

| | |
|---|---|
| **What** | Aplikasi SaaS Invoicing & manajemen piutang untuk transaksi B2B dan B2C. Membuat invoice, mengirim ke klien, memantau status pembayaran, dan mengelola aging piutang. |
| **Who** | Owner dan Admin Usaha (UMKM, jasa, dagang, vendor B2B). Bukan untuk akuntan profesional — bahasa awam, alur pendek. |
| **Why** | Usaha kecil menagih lewat WhatsApp dan catatan manual; invoice hilang, jatuh tempo terlewat, piutang tak terlacak. Aplikasi ini menyatukan penerbitan invoice, penomoran rapi, dan pemantauan piutang dalam satu tempat. |
| **Where** | Aplikasi web (browser desktop & mobile), multi-tenant per usaha, di-deploy sebagai container Docker di VPS. |
| **When** | Dipakai harian saat menerbitkan invoice, dan mingguan saat menagih piutang jatuh tempo. |
| **How** | Laravel 13 + Octane (FrankenPHP/Swoole) sebagai backend API & rendering, Inertia.js + Vue 3 untuk UI reaktif tanpa API terpisah, MySQL untuk data, Redis untuk cache/queue/session, Nginx sebagai reverse proxy. |

### Kepatuhan & Standar

- **UU HPP (Harmonisasi Peraturan Perpajakan)** — struktur pajak invoice mendukung PPN dan pencantuman DPP/nilai pajak terpisah; PPh tidak dihitung aplikasi, hanya dicatat sebagai referensi.
- **SAK EMKM** — laporan dan istilah mengikuti Standar Akuntansi Keuangan Entitas Mikro, Kecil, dan Menengah: pendapatan, piutang usaha, dan jatuh tempo sederhana tanpa jurnal berpasangan penuh.
- Nominal uang disimpan sebagai integer desimal (bukan float); pembulatan ditampilkan, bukan disimpan.

## 5. Jebakan Teknis yang Sudah Diketahui

- **Host CPU tanpa AVX2 (Intel i5-3470).** Vite 8 (rolldown) crash `Illegal instruction (core dumped)` — SIGILL 132. Wajib pin `vite@^7` + `laravel-vite-plugin@^2`. Plugin v3 mensyaratkan vite ^8, dan vite 7 tidak punya export `laravel-vite-plugin/fonts` — font Bunny dihapus dari `vite.config.js`.
- **Bind mount menutupi `vendor/` hasil build image.** Entrypoint menjalankan `composer install` bila `vendor/` kosong. Di mesin dev, `vendor/` host yang dipakai.
- **`env_file` dibaca saat container dibuat.** Mengubah `.env` lalu `docker compose restart` tidak berefek. Harus `docker compose up -d --force-recreate <service>`.
- **Nginx cache IP upstream.** Setelah `app` di-recreate, request bisa 502 walau `app` healthy — `docker restart web` memperbaiki.
- **Config cache menahan nilai lama.** Mengubah `.env` lalu `config:clear` saja tidak cukup bila worker Octane sudah memegang nilai; perlu `octane:reload` atau recreate container.
- **JANGAN pakai `URL::forceScheme('https')` di aplikasi ini.** `trustProxies(at: '*')` di `bootstrap/app.php` sudah cukup: Laravel membaca `X-Forwarded-Proto` sendiri, jadi request lewat tunnel menghasilkan URL `https://` dan request lokal tetap `http://`. Menambahkan `forceScheme` merusak akses lokal: generator URL adalah singleton dan **worker Octane bertahan antar-request**, sehingga satu request publik https "meracuni" worker — `http://localhost:8181` lalu mengeluarkan asset `https://localhost:8181/...` yang diblokir browser, dan halaman tampil **kosong** (Vue tidak pernah mount). Gejalanya menipu: `octane:reload` dan `--force-recreate` tidak menyembuhkannya permanen, karena racunnya datang lagi dari request publik berikutnya.
- **Fallback port di Nginx harus `443`, bukan port lokal.** Kalau `docker/nginx/default.conf` memakai `default 8181`, `X-Forwarded-Port` membocorkan `:8181` ke URL publik di belakang tunnel.
- **Port host bertabrakan dengan stack lain di mesin ini.** 8080 (ljk_web), 8090 (siakad_web), 33061 (ljk_db), 63791 (ljk_redis). Karena itu proyek ini memakai 8181 / 33071 / 63801.
- **Ekstensi GD untuk QR Code & PDF.** `simplesoftwareio/simple-qrcode` dan format image memerlukan modul GD pada PHP. Image dasar `php:8.4-cli` membutuhkan instalasi library `libfreetype6-dev` dan `libjpeg62-turbo-dev` sebelum `docker-php-ext-install gd`. Instruksi ini dimasukkan ke `Dockerfile` agar hasil build tetap persisten saat recreate.
- **Aset Image / Logo & QR Code di DomPDF Octane.** Menggunakan URL HTTP untuk merender gambar (logo, stempel, QR code) di DomPDF berisiko timeout atau terkena loopback networking container. Solusi terbaik adalah membaca file dari storage dan melakukan encode base64 (`data:image/png;base64,...` atau `data:image/svg+xml;base64,...`) langsung ke Blade template.
- **PHP 8.4 Null-Safe pada Template Cetak.** Pengguna baru yang belum mengatur profil usaha akan memiliki relasi `$invoice->user->businessProfile` bernilai `null`. Seluruh akses atribut profil usaha di template PDF wajib menggunakan null-safe operator (`$businessProfile?->tax_id`) untuk mencegah error fatal `Attempt to read property on null`.
- **KEBIJAKAN MUTLAK DATA PENGGUNA (DILARANG HAPUS).** Dilarang keras menjalankan perintah `User::delete()`, `truncate`, `migrate:fresh`, atau pembersihan data apapun di database MySQL `invoice_saas`. Data pendaftaran pengguna (termasuk user `1@x.com` / `Fg` dsb.) harus tetap utuh dan persisten. Pengujian otomatis wajib hanya menggunakan SQLite in-memory (`:memory:`) dan pengujian manual dilarang membersihkan user yang sudah ada.
- **Isolasi Mutlak Database Testing dari MySQL.** `phpunit.xml` bawaan memiliki `<env name="DB_CONNECTION" value="sqlite"/>` tanpa `force="true"`. Pada Docker container dengan environment `DB_CONNECTION=mysql`, PHPUnit tidak meng-override variabel environment yang sudah ada dari container OS, sehingga `RefreshDatabase` tanpa sengaja me-refresh database MySQL. Solusi permanen: (1) `phpunit.xml` diberi `force="true"`, (2) Dibuat file `.env.testing` dengan `DB_CONNECTION=sqlite` & `DB_DATABASE=:memory:`, (3) `TestCase::createApplication()` meng-override environment ke sqlite `:memory:` dan melempar fatal exception jika koneksi bukan sqlite.
- **Penyebab Nomor Rekening Tidak Muncul di PDF & Solusi UX Guiding.** Nomor rekening dan nama bank diatur terpusat di form **Profil Usaha** (`/profile/business`). Bila pengguna belum mengisi profil usaha, template PDF sebelumnya menyembunyikan kotak pembayaran (`@if`). Solusi: (1) Template `invoice.blade.php` ditambahkan blok `@else` fallback instruksi pembayaran resmi, (2) Ditambahkan banner peringatan global kuning/oranye di navbar (`AuthenticatedLayout.vue`) dan menu Profil Usaha di navbar utama, (3) Preview rekening & alert di form pembuatan faktur (`Invoices/Create.vue`), halaman detail (`Invoices/Show.vue`), dan ringkasan di `Dashboard.vue`, (4) Prop boolean `auth.hasBankAccount` dibagikan otomatis via `HandleInertiaRequests.php`.
- **Perilaku Tanda Nilai `diffInDays()` Carbon pada Tanggal Lampau.** Method `$today->diffInDays($dueDate)` pada Carbon secara default mengembalikan nilai negatif (`-10`, `-45`) bila `$dueDate` berada di masa lalu relatif terhadap `$today`. Pada logika pengondisian umur piutang, jika tidak dibungkus `abs()`, kondisi `if ($daysOverdue <= 30)` akan selalu bernilai benar untuk seluruh tanggal overdue (karena semua angka negatif <= 30). Wajib menggunakan `abs((int) $today->diffInDays($dueDate))` atau `$dueDate->diffInDays($today)`.
- **Route Cache di `bootstrap/cache/routes-v7.php` Menahan Route Bawaan.** Mengubah closure `Route::get('/dashboard', ...)` menjadi controller `[DashboardController::class, 'index']` di `routes/web.php` tidak akan terbaca jika rute pernah di-cache sebelumnya. Wajib mengeksekusi `php artisan route:clear` (dan `config:clear`) saat memigrasi rute closure ke controller class.
- **Foreign Key Constraint Violation saat Hapus Pelanggan/Faktur (RESTRICT vs CASCADE).** Tabel `invoices` awalnya mendefinisikan `$table->foreignId('client_id')->constrained()->restrictOnDelete()`. Ketika pengguna menghapus data pelanggan yang memiliki riwayat faktur, MySQL memicu QueryException error 1451 (`Integrity constraint violation: foreign key constraint fails`). Solusi permanen: (1) Migrasi baru `2026_11_12_000006_update_invoices_client_id_foreign_cascade` mengubah foreign key `client_id` menjadi `cascadeOnDelete()`, (2) `ClientController@destroy` dan `InvoiceController@destroy` dibungkus `DB::transaction` untuk secara eksplisit menghapus `invoice_items` dan `invoices` terkait dengan aman, (3) Pada UI `Clients/Index.vue` ditambahkan peringatan interaktif jika pelanggan memiliki faktur terkait, (4) Pada `Invoices/Show.vue` ditambahkan tombol "Hapus Faktur" lengkap dengan konfirmasi, (5) `HandleInertiaRequests` dan `AuthenticatedLayout` dilengkapi banner notifikasi flash message sukses & error.
